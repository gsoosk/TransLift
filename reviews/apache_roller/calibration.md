## App facts reviewers can rely on
- Transactions are hand-made in JPAPersistenceStrategy (app/.../business/jpa/JPAPersistenceStrategy.java): one thread-local EntityManager; `getEntityManager(true)` begins the transaction lazily (lines 244-246), called by store, remove, removeAll, refresh, getNamedUpdate, getNamedQueryCommitFirst. `flush()` (line 135) is the only commit. Reads go through `getEntityManager(false)` with no transaction open.
- So in every `programmatic-region` the unit of work really begins at the first write (or getNamedUpdate, or the pessimistic find), not at method entry: reads before that point auto-commit and belong outside the boundary. Say so in the boundary and drop those ops. Named queries use FlushModeType.COMMIT, so a query never flushes pending changes.
- `release()` (JPAPersistenceStrategy.java:144) rolls back and closes the EM, and PersistenceSessionFilter.doFilter (app/.../ui/core/filters/PersistenceSessionFilter.java:49-67, mapped to /*) calls it in a finally after every request. Consequence: an **implicit** record that contains writes is not "auto-commit per statement" — the writes are rolled back at the end of the request. Only 5 implicit records have own writes: 685187ad6b50, ac84d287fc5f, 8909aa567bec, f908407b1c70, ab7a64a31643.
- All 28 entities are mapped in per-entity *.orm.xml under app/src/main/resources/org/apache/roller/{weblogger,planet}/pojos/ with an explicit table element. Table names are not derivable from class names (User -> roller_user, WeblogBookmarkFolder -> bookmark_folder). No @Version anywhere: no optimistic locking. The only pessimistic lock is JPAPropertiesManagerImpl.java:155-156 (PESSIMISTIC_WRITE), now flagged correctly.
- 30 explicit regions have an empty `invoked_by`: 6 XML-RPC handlers (Blogger/MetaWeblogAPIHandler, dispatched by name by the Apache XML-RPC servlet), 5 `*Task.runTask` (run from TaskScheduler.java:190, see below), and manager methods called only from other regions. That is expected, not a defect.
